# 模块设计

## 1. 设计目标

应用运行在 Android 6.0、2 GB 内存、8 GB 存储的电视盒子上。设计优先级依次为：

1. 播放稳定；
2. 断网仍可启动；
3. 遥控器可完成核心操作；
4. 代码结构简单，便于没有 Android 经验的开发者理解；
5. 控制依赖、内存和磁盘占用。

第一版不实现 EPG、搜索、收藏、视频代理和 APK 自动更新。

## 2. 总体结构

```text
自有服务器 channels.json
          |
          v
  ChannelRepository
   /             \
ChannelApi     ChannelCache
          |
          v
      TvViewModel
       /       \
频道列表 UI   PlaybackController
                   |
                   v
                TvPlayer
                   |
                   v
          Media3 ExoPlayer
```

各层只处理一种问题：

- 数据层不操作播放器和界面；
- 状态层不直接持有 Android View；
- 播放层不知道频道列表如何展示；
- UI 只响应状态和用户输入。

## 3. 数据模块

### 3.1 `ChannelCatalog`

代表服务器返回的完整数据版本，包含版本号和频道数组。

### 3.2 `Channel`

代表逻辑频道。一个频道可以拥有多个 `ChannelSource`。相同频道的多个清晰度或备用地址不会在 UI 中重复显示。

### 3.3 `ChannelSource`

代表一个可播放地址，保存：

- URL；
- 清晰度和编码；
- `User-Agent`、`Referer`；
- 健康检测状态；
- 地区限制及非全天候标记。

请求头必须属于播放源而不是频道，因为同一频道的不同源可能需要不同请求头。

### 3.4 `SourceRanker`

负责排序备用源。它是无 Android 依赖的纯 Kotlin 逻辑，因此可以直接单元测试。

排序原则：最近检测可用、H.264、1080p/720p优先；4K、8K、地区限制和非全天候源降低优先级。

## 4. 网络与缓存模块

### 4.1 `ChannelApi`

只执行 HTTP GET，并返回原始 JSON。它不解释业务数据，也不决定失败时怎么办。

### 4.2 `ChannelCache`

把成功 JSON 写入应用私有目录。写入过程先创建临时文件，再替换正式文件，避免进程中断留下半个 JSON。

### 4.3 `ChannelRepository`

负责数据来源优先级：

```text
有效本地缓存
→ APK 内置示例
→ 后台请求远程数据
→ 远程成功后更新缓存和页面
```

启动不等待网络。这样服务器不可达时仍能显示上次频道列表。

## 5. 状态模块

`TvViewModel` 保存单一 `TvUiState`：

- 频道列表；
- 当前频道序号；
- 数据来源；
- 加载状态；
- 播放状态文字；
- 错误信息。

UI 通过 `StateFlow` 观察状态。换台只修改当前序号；Activity 观察到频道变化后通知播放控制器。

最后频道 ID 使用 `SharedPreferences` 保存。这里的数据量很小，无需数据库。

## 6. 播放模块

### 6.1 `TvPlayer`

封装唯一 ExoPlayer 实例，职责是：

- 根据单个 `ChannelSource` 创建 HTTP DataSource；
- 注入该源需要的请求头；
- 创建媒体项并开始准备；
- 把 READY、播放和错误事件通知上层；
- 在 Activity 销毁时释放资源。

### 6.2 `PlaybackController`

负责频道级播放策略：

1. 用 `SourceRanker` 排序该频道全部源；
2. 播放首选源；
3. 15 秒内未 READY 视为超时；
4. 播放器报错或超时后切换下一源；
5. 所有源失败后报告错误，但不退出应用。

`TvPlayer` 不自行重试，避免底层播放器和业务层同时重试造成状态混乱。

## 7. UI 与遥控器模块

`MainActivity` 使用一个全屏 `PlayerView` 和一个覆盖在视频上的频道面板。

频道面板使用 `RecyclerView`，支持遥控焦点和手机触摸。遥控规则：

- 上键、频道加：上一频道；
- 下键、频道减：下一频道；
- 左键：显示频道面板；
- 右键：隐藏频道面板；
- 确认键：切换频道面板显示状态；
- 返回键：面板显示时先关闭面板，否则退出 Activity。

频道切换后面板延迟隐藏。界面不使用复杂动画，降低老设备 GPU 压力。

## 8. 生命周期与资源

- Activity 创建时只建立一个 ExoPlayer；
- `onStart` 恢复播放；
- `onStop` 暂停播放；
- `onDestroy` 释放播放器、Handler 和网络资源；
- 不缓存视频；
- 第一版不加载网络 Logo，避免引入图片缓存和额外内存压力。

## 9. 安全与网络

CN 列表包含 HTTP 源，因此 Manifest 允许明文流量。应用自己的频道接口应使用 HTTPS。

远程频道地址通过构建参数提供，不把私人服务器地址提交到 Git。第一版仅请求固定配置地址，不提供任意网页或 WebView。
