# 代码实现说明

本文将设计映射到具体代码。阅读顺序建议：数据模型 → Repository → ViewModel → 播放器 → Activity。

## 1. 数据模型

`data/ChannelModels.kt` 使用 `kotlinx.serialization` 定义 JSON 契约：

```kotlin
@Serializable
data class Channel(
    val id: String,
    val name: String,
    val group: String = "其他",
    val sources: List<ChannelSource>
)
```

默认值用于兼容服务器逐步增加字段。Repository 会过滤空 ID、空名称和没有有效 URL 的频道，防止坏数据进入 UI。

## 2. 数据加载

`ChannelRepository.loadInitialCatalog()` 按以下顺序返回首屏数据：

```kotlin
cache.readCatalog() ?: assets.readSampleCatalog()
```

随后 `refresh()` 请求远程 JSON。只有 JSON 可解析且至少包含一个有效频道时才写缓存。

这意味着：远程服务器失败不会破坏可用缓存，启动也不会被网络阻塞。

## 3. 状态管理

`TvViewModel` 暴露只读状态：

```kotlin
private val _uiState = MutableStateFlow(TvUiState())
val uiState = _uiState.asStateFlow()
```

Activity 不直接修改状态，而是调用：

```kotlin
viewModel.selectChannel(index)
viewModel.selectNextChannel()
viewModel.selectPreviousChannel()
```

ViewModel 统一处理循环换台和最后频道恢复，避免按键处理里散落边界判断。

## 4. 播放请求头

`TvPlayer.play()` 为每个源建立独立 DataSource：

```kotlin
val headers = buildMap {
    source.referrer?.let { put("Referer", it) }
}
val dataSourceFactory = DefaultHttpDataSource.Factory()
    .setUserAgent(source.userAgent ?: DEFAULT_USER_AGENT)
    .setDefaultRequestProperties(headers)
```

然后把 DataSource 交给 `DefaultMediaSourceFactory`。不能只调用 `MediaItem.fromUri()`，否则需要 Referer 的源会直接失败。

## 5. 自动切源

`PlaybackController.play(channel)` 重置当前任务和超时计时器：

```text
排序 sources
→ index = 0
→ playCurrentSource()
→ READY：取消超时
→ ERROR/TIMEOUT：index++，播放下一源
```

控制器为每次播放源尝试递增播放代次。用户快速换台或自动切备用源时，旧源迟到的错误不能影响当前源。

## 6. Activity 与界面

`activity_main.xml` 的层级：

```text
FrameLayout
├─ PlayerView（全屏视频）
├─ 状态文字（左下）
└─ 频道面板（右侧）
   ├─ 当前频道标题
   └─ RecyclerView
```

`MainActivity` 收集 `uiState`：

- 列表变化时提交给 Adapter；
- 当前频道变化时调用 `PlaybackController.play()`；
- 播放状态变化时更新状态文字；
- 错误只显示，不销毁频道列表。

## 7. 构建配置

`local.properties` 中的服务器地址由 `app/build.gradle.kts` 读取并生成：

```kotlin
buildConfigField("String", "CHANNELS_URL", quotedUrl)
```

因此私人地址不会进入版本库。没有配置时，App 使用 `assets/sample_channels.json`，便于离线开发 UI 和解析逻辑。

## 8. 测试

- `ChannelJsonTest`：验证 JSON 契约和默认字段；
- `SourceRankerTest`：验证常规 H.264 1080p 源优先于 4K、地区限制或失效源；
- Gradle `testDebugUnitTest`：运行 JVM 单元测试；
- Gradle `assembleDebug`：证明 API 23 配置可以完成 Android 构建。

模拟器验收另行执行，重点检查 Android TV Launcher、焦点、遥控器和实际播放。
